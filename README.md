# Nishman.uz — лендинг официального дистрибьютора NISHMAN в Узбекистане

Одностраничный сайт (ru / uz / en) для барберов, магазинов (опт) и розничных покупателей.
Каталог из 201 товара (291 позиция «товар × объём × оттенок») собран из PDF-каталога бренда и студийных фото товаров (`img/`).

**Стек:** Next.js 16 (App Router, Turbopack) · TypeScript · Tailwind CSS 4 · framer-motion (только шторки, модалки и переключения внутри блоков; фичи грузятся асинхронно) · next-intl 4 · zustand (корзина в localStorage). Шрифт — системный стек как на apple.com (`-apple-system, BlinkMacSystemFont, "SF Pro Display", …`), веб-шрифты не загружаются. Карта — обычный виджет Яндекс Карт (iframe, `loading="lazy"`).

## Деплой

Продакшн: **https://nishman-uz.vercel.app** (Vercel, проект `nishman-uz`). Репозиторий GitHub подключён к проекту — каждый пуш в `main` деплоится автоматически, остальные ветки получают preview-ссылки.
Переменные окружения задаются в Vercel → Settings → Environment Variables (сейчас задан `NEXT_PUBLIC_SITE_URL`). После подключения своего домена обновите `NEXT_PUBLIC_SITE_URL`.

## Запуск

```bash
npm install
cp .env.example .env.local      # заполнить по необходимости (всё необязательно)
npm run dev                     # http://localhost:3000 → /ru
npm run build && npm start      # продакшн
```

Проверки: `npm run lint`, `npm run typecheck`, `npm run check:messages` (одинаковые ключи во всех языках и нет одинаковых текстов под разными ключами).

Требования: Node.js ≥ 20.9. Для пересборки каталога/видео — Python 3.11+ с `pymupdf pillow numpy imageio-ffmpeg`.

## Что нашлось в PDF и что пришлось придумать

PDF — 30 страниц (обложка, разворот с отзывом, «О нас», 4 раздела, заметки, задняя обложка). Каждая страница отрисована в PNG и просмотрена вручную; товары вшиты отдельными изображениями (200 шт.), поэтому фото собраны из исходников, а не вырезаны со скриншотов.

**Из PDF взято:** названия, коды, объёмы, фиксация (по точкам «Фиксация»), эффект (по пилюлям), свойства, заметки-пилюли («Для всех типов кожи» и т. п.), 123 фото товаров, 48 лайфстайл-фото, векторный логотип, факты бренда (Asil Group Cosmetic, Стамбул, 2016, экспорт в 40+ стран, «Creative Men Design»), отзыв А. Череповича (на сайте больше не используется).

**Не используется (по ТЗ):** контакты российского представительства (Москва, info@nishman.ru, nishman.ru, бот).

**Придумано (демо)** — см. таблицу ниже.

### Сборка каталога из PDF

```bash
python -I scripts/build-catalog.py assets/brand-catalog.pdf   # фото товаров + data/*.json + messages/catalog/*
python -I scripts/extract-logo.py                              # public/media/brand/nishman-{logo,mark}.svg
```

- `scripts/catalog_spec.py` — спецификация: каждый товар = код, линейка, тип, бренд-название, объёмы, эффект, фиксация, **ячейка сетки разворота**, откуда берётся фото; лайфстайл-фото по xref PDF и место их использования (каждое фото — ровно в одной секции; исключение — постер hero, который также кадр видео).
- `scripts/catalog_texts.py` — все тексты каталога на ru/uz/en (один текст = один ключ).
- Фото товара — композиция всех вшитых изображений ячейки (например, банка + пульверизатор) на прозрачном фоне; у JPEG без маски белый фон удаляется заливкой от краёв. Формат WebP; next/image отдаёт AVIF/WebP с srcset.

### Студийные фото товаров (`img/`)

218 студийных фото на белом фоне (`img/photo_2026-10-29_<время>.jpg`) собираются тем же скриптом:

- `catalog_spec.STUDIO` — `id товара → [время, …]`: первое фото становится главным (заменяет вырезку из PDF), остальные идут в галерею перед лайфстайл-фото. Без записи в `STUDIO` остаётся фото из PDF (расчёски, щётки, пеньюары, CP, G1, пилинг-гель, салонный кондиционер — их нет среди студийных).
- `SHADE_PHOTOS` — фото отдельных оттенков (цветной спрей, консилер, загуститель): при выборе оттенка в карточке галерея переключается на его фото, а в корзину попадает его миниатюра. `PDF_MAIN` — товары, у которых главным остаётся общее фото серии из PDF.
- Обработка: белый фон удаляется (фон = светлые пиксели, связанные с краем кадра), товар определяется по выпуклой оболочке тёмных деталей — так белые банки и флаконы не «просвечивают»; тень и отражение становятся полупрозрачными, подпись с объёмом под товаром («150 мл», «20 г») вырезается.
- 22 фото — дубли кадров (повторы 2-фазных кондиционеров, одеколонов 0/1, аква-воска, M1/M2, PION) и не используются.

По фото добавлено 78 товаров: дезодоранты 01–06, гели и скрабы для душа, воск для депиляции (новый раздел «Тело»), 2-фазные кондиционеры 2–5, гели для бритья 9 и Smooth, одеколон 0, гель-воски B1–B4, B6, B7, B9, пудры P1 (Fresh Look, Flaming, Sport, Gumgum), P0, X1, X5, M10–M12, A2, U1, F2, Milky, Black Edition 10, пена-воск, крем для кудрей, бриллиантин, гель 5+ Sea Salt, Jellyboom, лак Sea Salt, шампуни XL, PION, мусс Milk, спрей-блеск, миноксидил, оттеночные шампуни, пена FC, карандаши для бороды, наборы, скрабы и маска Exclusive, маска Kabuto, тоник для лица, полоски для носа, полотенца, воротнички, спрей для машинок. Названия, коды, объёмы, фиксация (по точкам HOLD) и свойства — с надписей на упаковке; цены — демо. У существующих товаров по фото добавлены объёмы: одеколоны 400 ml, гели для бритья 1500 ml, тоник 400 ml, масло для бороды 100 ml, кондиционер 1250 ml, лак 05 769 ml (салонный), пудра P1 160 g (салонная).

**Проверить у клиента:** объёмы гель-скраба Strawberry и геля Pure Touch (на фото не видны, принято 400 ml), спрея-блеска (400 ml), Sea Scrub (300 ml) и банок Exclusive/Kabuto (500 ml); Kabuto Katana и PION — другие бренды Asil Group, оставить ли их в каталоге NISHMAN.

Кодам товаров в PDF соответствуют `code` (01, M2, S3, C1, 5+, 1|2, T-121…). Поскольку коды не уникальны (у двух гелей «5+», «01» у многих линеек), идентификатор товара — `id` (`gel-5plus-argan`), фото: `public/media/products/<id>.webp`.

Поля `products.json`: `id, code, line, category, type, name, scent, variant, volumes[{value, unit, price, demo}], effect, hold, holdPlus, features[], notes[], forSalons[], size, shades[], swatch, image, gallery[], source.pdfPage`. Тексты (`type`, `scent`, `features`…) — ключи в `messages/catalog/*`; `JsonCatalogProvider` отдаёт UI уже локализованные строки.

**Решения по данным, которые стоит подтвердить у клиента:**
- `effect`: кроме «матовый / естественный блеск / полуматовый» добавлено значение **`natural` («Естественный эффект»)** — так подписаны пудры в PDF. Где эффект в PDF не указан (гели, лаки, уход) — `null` («без эффекта» не придумывался).
- `hold`: 0 — «Без фиксации» (цветной воск, цветной спрей), `null` — фиксация не указана (Black Gel и уход). `holdPlus` — «5+» (●●●●●+).
- Шампуни 01–03: в PDF общий ряд объёмов «200 · 400 · 1250 · 5000 ml»; 5000 мл отнесён к Salon Size, у 01–03 оставлены 200/400/1250. Салонный кондиционер — 5000 мл (как у салонного шампуня).
- Масло для бороды: в PDF общий ряд «30 · 75 ml» для обоих масел — указан у обоих.
- M5: в PDF надпись объёма наложена («30·100 ml» поверх другой) — принято 30 · 100 ml как у всей матовой линейки.
- Одноразовые полотенца «70×40 mm» — в PDF так; вероятно, сантиметры.
- Цветной спрей, консилер и загуститель — по одному товару с выбором оттенка (в PDF одно фото на всю серию).

- **Тексты интерфейса** — `messages/{ru,uz,en}.json`. После правок: `npm run check:messages`.

- **Фото** — какие кадры PDF куда идут, задаёт `PHOTOS` в `catalog_spec.py`; своё фото можно положить в `public/media/models/` и прописать в `data/photos.json`.

### Видео hero

Сейчас — зацикленный ролик 10 с, собранный из 4 фото моделей PDF (медленный zoompan + xfade, тёмный цветокор, бесшовный цикл): `public/media/video/hero-{desktop,mobile}.{mp4,webm}` (десктоп 1280×720 ≈ 1.25 МБ, телефон 540×960 ≈ 0.7 МБ, H.264 faststart + VP9) и постеры AVIF/WebP (первый кадр).

Заменить своим: положите `assets/hero.mp4` (или `.mov`) и запустите
```bash
python -I scripts/build-hero-video.py <папка-с-кадрами> public/media/video
```
Скрипт перекодирует ролик в оба размера и снимет постеры. Без своего ролика он собирает видео из PNG-кадров (`hero-barber/spray/comb/cans.png`, выгружаются `build-catalog.py` при передаче второго аргумента).

Логика загрузки: постер — LCP (preload, art direction по `media`), видео стартует после `load` в `requestIdleCallback`, `preload="none"`, muted/playsInline/loop/aria-hidden/disablePictureInPicture, пауза вне экрана и на скрытой вкладке. Видео не грузится при `prefers-reduced-motion`, Save-Data, сети 2g/3g и заряде < 20 % без зарядки. На сайте один `<video>`.

## Каталог: интеграция с учётной системой

UI работает только с интерфейсом `CatalogProvider` (`lib/catalog/types.ts`):

```ts
getProducts(locale, query?) · getProduct(locale, id) · getCategories(locale) · getLines(locale) · createOrder(input)
```

Сейчас — `JsonCatalogProvider` (`lib/catalog/json-provider.ts`). Для 1С / МойСклад / собственного API реализуйте тот же интерфейс и верните его в `getCatalog()` (`lib/catalog/index.ts`). `createOrder` должен проверять позиции и цены на стороне источника — сервер не доверяет ценам из браузера.

Заказы: `OrderService` (`lib/orders/order-service.ts`) → `CatalogProvider.createOrder` → `PaymentProvider.init` → уведомление в Telegram. Номер заказа: `NM-ГГММДД-XXXX`.

## Платежи (Click, Payme, при получении)

`lib/payments/providers.ts`: `ClickProvider`, `PaymeProvider` (заглушки), `CashProvider`. Без ключей онлайн-оплата не инициируется: заказ принимается, покупатель видит «менеджер пришлёт ссылку на оплату».

- **Click:** `CLICK_SERVICE_ID`, `CLICK_MERCHANT_ID`, `CLICK_MERCHANT_USER_ID`, `CLICK_SECRET_KEY`. Ссылка формируется на `my.click.uz/services/pay`. Вебхук Prepare/Complete — `POST /api/payments/click`: проверить подпись `sign_string` (md5), сумму и статус заказа в учётной системе (TODO в коде).
- **Payme:** `PAYME_MERCHANT_ID`, `PAYME_SECRET_KEY`, `PAYME_TEST_MODE`. Ссылка — `checkout.paycom.uz/<base64>`. Merchant API (JSON-RPC: CheckPerformTransaction, CreateTransaction, PerformTransaction, CancelTransaction, CheckTransaction, GetStatement) — `POST /api/payments/payme`, авторизация `Basic Paycom:<key>` уже проверяется.
- В личных кабинетах укажите URL вебхуков `https://<домен>/api/payments/click` и `/api/payments/payme`.

## Telegram-бот

1. Создайте бота у @BotFather → `TELEGRAM_BOT_TOKEN`.
2. Добавьте бота в чат/канал менеджера, узнайте `chat_id` (например, через `https://api.telegram.org/bot<token>/getUpdates`) → `TELEGRAM_CHAT_ID`.
3. Заявки «Партнёрам» и заказы приходят сообщениями. Защита: валидация на сервере, honeypot, лимит 5–6 запросов в минуту с IP (в памяти процесса; для нескольких инстансов — вынести в Redis).

## Карта

Обычный виджет **Яндекс Карт** (`yandex.uz/map-widget/v1`) в iframe: стандартная светлая карта с названиями улиц и объектов, без фильтров, оверлеев и перекраски. На карте — стандартные метки всех точек (виджет не поддерживает свои цвета и номера меток); нажатие на фото точки в списке показывает её крупным планом, повторное — возвращает общий план. «Маршрут» открывает построение маршрута в Яндекс Картах. Ключ API не нужен. Настройки (центр, масштаб) — `site.config.ts → map`, координаты точек — `site.config.ts → stores`. iframe грузится лениво (`loading="lazy"`), поэтому не влияет на первую загрузку.

## Реализация ТЗ: ключевые моменты

- **Правило «один раз»:** полные контакты — только в «Контактах» (в остальных местах — кнопки-иконки); категории — только в индексе каталога; цифры бренда — только в hero; доставка — только в «Адресах» (в оформлении — лишь названия способов); оплата — только в оформлении; каждое лайфстайл-фото — в одной секции (`PHOTOS` в `catalog_spec.py`); в переводах нет одинаковых текстов под разными ключами (`npm run check:messages`).
- **Телефон:** нижняя панель «Позвонить / Telegram / Корзина», плавающие кнопки — только десктоп; меню на весь экран; фильтры, быстрый просмотр и корзина — bottom sheet с блокировкой фона и липкой кнопкой; карусели со snap; квиз — по вопросу на экран; safe-area и `svh` (высота hero не прыгает при скрытии адресной строки); цели касания ≥ 44 px.
- **Анимации (в духе apple.com):** параллакса, привязки к прокрутке, JS-сглаживания скролла, кастомного курсора и «магнитных» кнопок нет. Блоки появляются при прокрутке через один общий IntersectionObserver (`components/motion/reveal.ts`): CSS-переход opacity + translateY 24 px, 0.9 с, кривая `cubic-bezier(0.22, 1, 0.36, 1)`. Анимируются только `transform` и `opacity`; scroll-обработчиков нет (подложка шапки — тоже через IntersectionObserver). Без JS всё видно сразу (класс `.js` на `<html>`), `prefers-reduced-motion` отключает появление и переходы.
- **Квиз:** подбор по полям `effect` и `hold` (длина волос — мягкий тай-брейкер по типу линейки), 3 результата из разных линеек.
- **Счётчики hero:** «150+ позиций» = число SKU (товар × объём × оттенок = 192), округлённое вниз до 50; «40+ стран» — из PDF.

## Проверки (продакшн-сборка, локально)

- `lint`, `typecheck`, `build`, `check:messages` — без ошибок; страницы `/ru /uz /en` — SSG.
- 360×800, 390×844, 1440×900 во всех трёх языках: горизонтального скролла нет, ошибок консоли нет; якоря попадают точно (телефон и десктоп).
- Сценарии (puppeteer): быстрый просмотр → выбор объёма (цена меняется) → корзина → оформление (4 шага) → «Заказ принят NM-…»; фильтры в шторке; меню; квиз.

- Первый JS ≈ 207 КБ gzip (без nomodule-полифиллов): React 19 + рантайм Next 16 ≈ 130 КБ, остальное — ядро framer-motion и код страницы. Цель «~180 КБ» не достигнута; дальнейшее снижение — замена framer-motion на CSS/WAAPI в части секций.
- **Lighthouse (локально, `next start`, 29.10.2026):** телефон — Performance 93–96 (FCP 1.1 с, LCP 2.5–3.0 с, TBT 130–220 мс, CLS 0), Accessibility / Best Practices / SEO — 100; десктоп — Performance 99 (LCP 0.7 с, CLS 0), остальное — 100.
